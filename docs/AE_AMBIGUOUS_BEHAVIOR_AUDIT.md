## 3. 原因

| # | 原因（コード） |
|---|---|
| 1 | `shouldAutoResolve()`（engine.js）：火種0で「借りて意味があるか」の判定が、①三連が出ている時の序盤ルール（即発動）より後にあった。②`borrowWorthwhile()` が「全滅を避けられるか」を見ていなかった。三連・撃破・効用+7 のみで判断していた |
| 2 | `_enemyDefeated()` で `debtCarry = true` → 次の `_startCombat()` が `fight.debt` を復活させていた。仕様として意図された挙動だったが、ユーザー意図「借りの代償は現在戦闘内で完結」と矛盾していた |
| 3 | `scriptBand()` は「このまま発動したらどうなるか」を正しく示す。しかし、この解決で幕が替わる時、帯の「次」は新しい幕のコマになる。台本送りは今の幕の中で1コマ進めるため、送り先は帯に出ない。この区別の表示がなかった |
| 3b | 第1幕の値は、怒り（実ターン数）で増える。借りの1コマは実ターンを進めない。値の差を説明するツールチップがなかった |
| 4 | 台本送りの後も、通常の操作と同じく `afterManip()` → `needsDecision()` で判定していた。台本送りは「敵の行動を変える」操作なのに、変わった盤面を見る機会がなかった |
| 5 | 設定文言「三連で止まる」が、効く条件（継ぎ留め・拍子木の解放後のみ）を書いていなかった |
| 6 | `screens.js` の灯の予測行が、倍率前の値を表示していた |
| 7 | 文言が固定（灰燼にも「強撃」） |
| 8 | 設定行のレイアウト（横並び固定） |

## 5. 修正内容

### core（`js/core/engine.js`）

- **借りの持ち越しを削除（#2）**：`debtCarry` の設定・`_startCombat` の復活・`f.debtCarried`・待機中の帯の借りコマを削除。借りた手で撃破したら、借りはその戦闘で消える。新しい戦闘は常に、借りなし・未払いなし・借り火を再び使える状態で始まる。
- **火種0の停止条件（#1）**
  - `borrowWorthwhile()`：借りた火種1でできる全ての1手（ずらし（保持を外して）、写し身、運命の鍵、台本送り）を、複製で試す。次のどれかなら「意味がある」とする。
    - 三連・絆になる
    - 撃破できる
    - **全滅を避けられる**
    - HP が5以上多く残る
    - 8以上多く削れる
    - 予測の価値が+7以上
  - ダイス（再演・ダイス由来のコマ）は見ない。
  - 内部は `_borrowOutcome()` と `Run._material()` に分けた。
  - `shouldAutoResolve()`：序盤の「三連は即発動」の前に、借りが意味を持つかを確認する。`return this._anyAction(false) || !this.canBorrow();`
- **台本送りしたターンは自動発動しない（#4）**：`shouldAutoResolve()` の先頭で `if (this.fight && this.fight.advanced) return false;`
- **幕替わりの印（#3）**
  - `previewTurn()` が `phaseBefore`／`phaseAfter`／`debtPhase` を返す。
  - `scriptBand()` は、解決で幕が替わる場合に、新しい幕のコマ（次／その次／借り）へ `actChange` を付ける。
- `debtAction` イベントに `phase` を追加（借りのコマがどの幕のものか）。

## 10. 残る不確実性

- **借りで撃破した時の代償**：持ち越しをやめたため、借りで撃破したターンは代償がない。sim では借り回数・勝率・時間に差は出なかった。人間が「撃破できる時は常に借りる」に寄るかは未測定。
- **「意味がある」の閾値**：HP5、ダメージ8、効用+7 は、毎ターンのクリックを増やさないための線。境界の局面で「止まってほしかった／止まらなくてよかった」と感じるかは、人間での確認が必要。
- **ダイスを見ない**：再演や、ダイス由来の借りコマで得られる結果は「意味」に数えない。この理由で止まらない局面は残る。
- **最後の操作後の継ぎ**（#12）：送りをしないターンで、最後の有料操作の後に無料の継ぎだけが残る場合は、従来どおり自動発動する。
- **「幕」札の読みやすさ**：小さい札（36〜42px）の上に載る。低い表示倍率での判読は未確認。
- **手動確認の環境**：Claude in Chrome（実 Chrome）ではなく、アプリ内ブラウザで確認した。初期状態の設定にはテスト用のフックを使った。
- #10・#11・#13 は原因未確定のまま。
