# Phase 2 バーティカルスライス — A-lite「灰輪の台本」＋ E「残り火の一手」

2026-10-07 実装。基準は初期版（git `89b29f1`）。設計の経緯は `playtests/SlotDungeon_10Run/`（Dots 10 Run 調査。ローカル専用で GitHub には無い）と、その後の拡張検討（A-lite＋E を採用、認知曲線 0〜120 分）に基づく。

---

## 1. 今回の目的

「敵の予告に応えるゲーム」から「**敵に何をさせるかも選ぶゲーム**」へ進む認知が、実際に遊んで面白いかを検証できる状態にすること。コンテンツ量は増やさない。

- A-lite：敵の未来の行動を「台本の帯」として見せ、それを **1コマ送る** 能動操作だけを足す。
- E：火種0で「正解は見えるのに回すしかない」状態に、**未来を担保にした一手** を残す。
- 後半だけ、三連・絆の自動発動で判断を奪わない。

---

## 2. 採用した最終仕様（要約）

| 要素 | 内容 |
|---|---|
| 灰輪の台本（帯） | 予告を `今 → 次 → その次` の小札で表示。B5以降、または【拍子木】【借り火】を灯した後。B1〜4は従来どおり |
| 【拍子木】／台本送り | 1ターン1回・火種1。今の予告を行わせず、次の行動を「今」にする。敵ターンは経過しない |
| ロック | 溜め終えた **強撃（heavy）と灰燼** は送れない（早めることはできる）。帯と予告板に真鍮の南京錠 |
| 【借り火】／灰輪に借りる | 火種0・1戦1回。このターンだけの火種1。代償として灰輪は **次のコマもこのターンに行う** |
| 三連・絆の自動発動 | 【継ぎ留め】か【拍子木】の後は、撃破しない三連/絆は介入余地がある限り止まる。設定で「すぐ発動」に戻せる |

## 3. 追加した灯紋（2つ）

| 灯紋 | 系統・位置 | コスト | 前提（いずれか） | 種別 |
|---|---|---|---|---|
| 借り火（借） | 運・リング2（押し手の左上、賭博師の目の手前） | 55 | 押し手 | 新しい操作 |
| 拍子木（拍） | 運・リング4（継ぎ留めの上、運命の鍵の手前） | 100 | 継ぎ留め／蓄え | 新しい操作 |

- **借り火を早めに置いた理由**：Dots 調査で最も多い負の体験（Run2・3 の B8 火種切れ）は、Run 2〜4 で起きる。灯紋の発見は「後悔 → それを解く灯紋」の流れに乗せている。
  - 死亡画面のささやきに追加した条件：完全に操作不能なターンが2回以上、または火種0で倒れた。
- **拍子木の位置**：「次のターンを今から組む」継ぎ留め（運）か、「盾を前のターンから積む」蓄え（守）の先に置いた。どちらも数ターン先を考える灯紋で、目安は B8 突破前後・Run 6〜8。
  - 死亡画面のささやきに追加した条件：修道院長の蘇生で取り戻されたHPが多い、強撃で多く削られた、逆廻りで倒れた。
- **【拍子木】は火種を灯す**：守系統だけで到達した場合でも火種を得る（押し手／再演を持たない場合の詰みを防ぐ）。

## 4. 敵台本のルール（core: `js/core/engine.js`）

**状態**
- `e.cursor`（台本の位置）と `e.turn`（実際の敵ターン数）を分離した。
- `data.js` の `ai()` は台本を `cursor` で読む。時間で強くなる効果（灰輪の加速）だけが `turn` を読む。
- 台本を送っても `turn` は増えない。燃焼の減少、スライムの成長、灰輪の加速、連鎖の再装填は起きない。

**一コマの消費**（`Run.scriptTick`）
行われた／飛ばされたコマの痕跡（破滅の秒読みのカウント、`lastK`）を、どちらの場合も同じ規則で残す。次のものは全て「台本のコマを消費する」操作として統一した。
- 実行
- 台本送り
- 怯み（強撃のコマを消す）
- 借りの取り立て

**怯み**：盾2つで構えを止めると、強撃のコマが台本から消える。帯では「不発」と打ち消し線で見える。従来の挙動と同値で、回帰試験で同一性を確認済み。

**未来予告の正確性**
未来は **状態の複製** で計算し、実際の敵・RNG・AI 内部状態には触れない。

| 状況 | 計算方法 |
|---|---|
| idle（回す前） | 軽量な影（ghost）で台本を読み進める |
| spun（回した後） | 現在の発動列で Run の複製を `resolve()` し、その結果の「次」を表示（完全一致） |

帯には推測を出さない。分からないものは正直に示す。

| 表示 | 意味 |
|---|---|
| `？` | サイコロが決める（燭ネズミの行動、サイコロで決まった借りのコマとその後） |
| `?`（紫） | 灰輪の幕替わり（全封印が割れる／HP30%）が起き得る。連鎖の追加スピンの目しだい |
| `盾`（青） | 次のスピンで盾2つが出れば怯みで消える強撃。その後ろのコマは `?`（繰り上がる） |

連鎖の追加スピンは覗き見しない。複製では連鎖を止め、起きる場合は不確定扱いにする。

**対象敵**：B5以降の固定サイクル敵すべてで一貫して動く。修道院長の `mostStocked` は戦闘中は不変（呪いの一時髑髏は数えない）なので、正確に予告できる。

| 敵 | 台本送りでできること |
|---|---|
| 骸骨衛兵・深淵の衛兵 | 攻撃 → 防御 → 構え → 強撃。強撃を早めて棘・蓄えで受けられる。強撃自体は送れない |
| 骨の修道院長 | 封じ → 断罪 → 呪詛 → 蘇生。蘇生を飛ばせる。封じた目と発動列の関係が変わる |
| 影の写し身 | 鏡の構えを攻撃ターンへ送れる |
| 灰輪の主 | 封印中の4手、逆廻りの封じ順（剣 → 焔 → 盾 → 癒）、破滅の秒読み（灰燼は送れないが早められる） |

## 5. 灰輪に借りるルール

- **条件**：火種0、1戦1回、手に借りた火種がないこと、未払いの借りがないこと。
- **借りた火種**
  - そのターンだけ使える。全ての「火種1」の操作（ずらし／再演／写し身／運命の鍵／台本送り）に使え、手持ちより先に使われる。
  - 発動時に消え、貯めることはできない。その後の三連・灯による火種の獲得は通常どおりで、借りた分は加算されない。
- **代償**：その敵ターンで、灰輪は今の行動の後に **台本の次のコマも行う**（台本が1コマ先取りされる）。
  - 怯みで強撃が消えた場合は、その後ろのコマを行う。踏み倒しはできない。
  - 借りた火種を使わなくても代償は発生する。
- **戦闘が先に終わった場合**（借りた手で撃破したとき）：借りはその戦闘で消える（次の戦闘へは持ち越さない）。借り・代償は「今の戦闘の中で完結する」。新しい戦闘は常に、借りなし・未払いなし・借り火を再び使える状態で始まる。
  - 2026-10-08 曖昧挙動監査で変更（旧：次の敵が最初のターンに2コマ行う）。理由と影響は `docs/AE_AMBIGUOUS_BEHAVIOR_AUDIT.md`。
- **プレビュー**：「灰輪に借りる」にホバーすると、次の2つが出る。
  - 帯に赤い「借り」のコマ。
  - 予測パネルの1行（例：`借りの一手：断罪 も このターンに / 予告 14 ＋借り 6 − 盾 7 → 被ダメ 13`）。
- **【血の代価】との役割**：血の代価は「自分の肉体で払う」（HP4で再演、何度でも）、借り火は「敵の未来で払う」（1戦1回、全ての火種操作に使える）。共存させている。

## 6. 自動発動の新ルール

| 状況 | 挙動 |
|---|---|
| 序盤（継ぎ留め・拍子木なし） | 従来どおり、三連・絆・撃破は即発動 |
| 継ぎ留め or 拍子木 あり | 撃破しない三連/絆は、何か介入できる限り止まる |
| 撃破できる発動 | 常に即発動（従来どおり） |
| 何も介入できない | 即発動（従来どおり） |
| 火種0 | 【借り火】が使え、借りた1手（ずらし・写し身・運命の鍵・台本送り）で「三連/絆になる・撃破できる・全滅を避けられる・HP5以上多く残る・8以上多く削れる・予測の価値+7以上」のどれかになるときだけ止まる。三連が出ていても同じ（借りる/借りないの選択を飛ばさない）。それ以外は自動発動 |
| 台本送りをしたターン | 火種が尽きても、何もできなくても、自動発動しない。送った後の盤面を見て Space で発動する（送った後もずらし等は続けられる） |

止まったときは、理由を予測パネルに1行で出す（回復が溢れる／受ける攻撃がない盾の三連／台本を送れる／留めを決められる）。設定「三連・絆で止まる」の「常にすぐ発動」で従来の挙動に戻る（継ぎ留め・拍子木が未解放の間は、設定にかかわらず常にすぐ発動。設定欄にその旨を表示）。

**fuzz の内訳**：純粋性 98,142 件、ダメージ予測一致 148,278 件、帯「次」一致 125,358 件、idle 帯 99,250 件、台本送り 16,914 件、借り 924 件、借りのコマ 791 件、不発表示 970 件。fuzz が検査する不変条件は次のとおり。

- 帯の「次」と実際の予告が一致。
- 予測ダメージと実ダメージが一致。
- 借りた火種はターンを越えない／1戦1回／取り立ては1回。
- ロックされたコマは送れない／台本送りは1ターン1回。
- 灰燼の予測が一致。

**unit の内訳**：台本の位置とターンの分離、強撃ロック、燃焼・成長・加速が進まないこと、灰輪の封じ順と破滅の秒読み、蘇生を飛ばす、鏡の構え、プレビューの純粋性、借りの規則（貯められない・持ち越さない・1戦1回・怯みとの組み合わせ・撃破したら借りは消えて次戦は白紙）、火種0の挙動、自動発動の停止条件、ボスの幕替わり、レビュー修正、旧セーブの読込と保存。

**敵対的レビュー**：4つの観点×各発見に懐疑役2人のワークフロー（36エージェント）を実行した。16件の発見のうち14件が検証を通り、全て修正した。主なもの：
- 台本送りが【精妙】を誤って発動させた。
- 守系統だけで拍子木を買うと火種がなく使えなかった。
- 連鎖の追加スピンやサイコロで決まる借りのコマが、予測から透けて見えた。
- 構えの後の強撃が「確定」と表示されていた。
- 借りが戦闘終了で消えた。
- 反射が被ダメ表示から漏れていた。
- capture.js の構え演出が壊れていた。

## 9. シミュレーション結果

`tools/sim.js` に次を追加した。

- ボットの借り判断：借りた1手の最良の使い道と、借りの代償を比べる。
- 計測モード：`metrics <strategy> [n]`、`script [n]`。
- キット：`*+A`、`mid+E`。
- 購入順：`legacy`（拡張前の順）。

**Run 1（spin のみ, n=2000）**：B4 で死亡 71.4%、犬の撃破 28.6%、残HP中央値 28%、約 118 秒。**初期版と同一**。

## 10. 手動プレイ結果（アプリ内ブラウザ）

アプリ内ブラウザのペインが非表示で requestAnimationFrame が間引かれるため、次の方法で操作した。
- 演出待ちを即時化し、フレーム更新を手で送った。
- その上で、実画面の UI ロジック（`RunScreen` の操作関数・ホバー・ボタン）で、1手ずつ自分で判断して遊んだ。
- 見た目はスクリーンショットで確認した。人間の速度での体感テストではない。

**確認できたこと**
- **帯の表示と一致**：吸い火・呪い蛾・衛兵・修道院長・灰輪の各幕で、帯の「次」が実行と一致した。予測ダメージも実被ダメと一致した。
- **送ると次が変わる**：例えば次のとおり。
  - 蛾の呪い → 攻撃7 を今に。盾ペアで受け、棘で4返して呪いを回避した。
  - 修道院長の蘇生 → 剣封じを今に。発動列に剣がない時を選んだ。
- **強撃を早める**：怨念衛兵戦で、防御のコマを送って敵の防御を消し、強撃を今に呼んで、1ずらしで撃破した。
- **「避ける」だけではない**：同じ戦いで、送らずに怯みで強撃を消す判断も成立した。帯に「不発」と表示される。
- **蘇生を飛ばせる**：修道院長の蘇生10と防御6を飛ばした。
- **借り火で助かるが、その後が危険**：HP20・火種0で、1コマ先の回復三連を借りて全快した。代償として敵は防御10も行い、強撃が1ターン近づいた。
- **毎回借りるのが最適には見えない**：修道院長戦で、1手では三連が組めない局面のプレビューが `予告 14 ＋借り 6 → 被ダメ 13` を示し、借りないことを選んだ。
- **後半の三連で止まる**：満HPの回復三連が「回復が溢れる」で止まった。焔の三連は「台本を送ってから発動」で止まり、送ってから発動した。
- **ボスで意味を持つ**：逆廻りで剣封じのとき、発動列の剣を活かすため焔封じへ送った。第3幕では秒読みを送って灰燼を早め、灰燼自体はロックされた。

**感触（AI プレイヤーとしての所感）**
- 帯が見えるだけで、「次のターンに何をさせたいか」を毎ターン考えるようになった。送るかどうかの迷いが、ずらしと火種を取り合う。
- 送った結果が予測パネルと帯に即座に出るので、「予測 → 操作 → 結果」の手触りは保たれている。
- 一方、局面によっては「攻撃を1回消す」だけの使い方が手軽で、最初に選びがちだった。

## 11. 既知の問題・懸念

- **使い方の偏り**：ボットの台本送りは通常攻撃の回避に偏る（§9）。人間も同じなら、火種1で攻撃を消す選択が「ずらし」と競合する手軽な守りになる。
  - 未調整の打ち手：攻撃のコマは火種2、送ったコマを次のコマに上乗せ、など。
- **影の写し身**：鏡の構えは全ビルドが送る。敵の個性が「火種1で消せる」に寄る恐れがある。
- **三連停止のテンポ**：継ぎ留め所有後は、撃破しない三連ごとに1回 Space が増える。人間での負担は未測定（設定で切れる）。
- **帯の読みやすさ**：小札は 36〜42px。低い表示倍率では小さい。`?`（紫）・`盾`（青）・`？` の意味の区別は、ツールチップ頼み。
- **右パネルの過密**：写し身・運命の鍵・台本送り・借りが全て灯ると、密度を上げた配置で収めている。ヘルプ行の末尾が設定ボタンに少し掛かることがある。
- **借りで撃破したときの代償**：監査（2026-10-08）で持ち越しをやめたため、借りた手で撃破したターンは代償がない。シミュレーション上の影響は誤差の範囲（`docs/AE_AMBIGUOUS_BEHAVIOR_AUDIT.md` §8）。
- **プレビュー計算**：ホバーごとに Run の複製を解決している。デスクトップでは問題ないが、低性能端末では未計測。
- **シミュレーションの限界**：時間モデルは従来のまま。人間の初クリア時間・初クリア後の継続意欲は未計測。
- **既存の仕様（変更していない）**：ずらしで撃破できる状態にしても自動発動せず、Space が必要。

## 12. 次のプレイテストで確認したい仮説

1. **新しい認知が生まれるか**：プレイヤーが敵を「強い／弱い」ではなく「どのコマが欲しいか」で語るか。
   - 例：「衛兵の強撃を呼ぶ」「蘇生の前に送る」「剣封じを焔封じへ回す」。
2. **送るが多目的になるか**：強撃を早める・蘇生を飛ばす・封じ順を回す・防御を消す、が出るか。通常攻撃を消すだけに収束しないか。どのタイミングで「早める」発想が出るか。
3. **借り火は判断として機能するか**：「回すしかない」時間が減るか。毎回借りる・一度も借りない、のどちらかに固定されないか。借りの代償がプレビューで理解されるか。
4. **三連停止は主体性か摩擦か**：止まったときに別の行動を選ぶ割合と、ただ Space を押す割合。
5. **帯は直感的に読めるか**：「敵にも未来の並びがある」とすぐ分かるか。`？`・`盾`・南京錠が誤読されないか。
6. **序盤25分の体験が保たれるか**：第一層の印象が変わっていないか。B5 で帯が出たときに情報過多と感じないか。
7. **初クリアの時刻と、その後の再挑戦理由**：初クリアが 50〜65 分に収まるか。クリア後、ビルドごとに違う送り方を試したくなるか。
