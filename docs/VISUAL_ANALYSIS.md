# EMBERWHEEL ビジュアル設計分析 — 再現可能な設計原則への変換

> 目的: EMBERWHEEL の見た目を「再現可能な設計知識」に変換し、将来の `procedural-character-harness` の土台にする。
> 根拠: 実装コード（`js/art/*.js`, `js/game/scene.js`, `fx.js`, `director.js`, `css/style.css`）、制作時のエージェント指示書・自己批評ログ、レビュー指摘と修正履歴（`docs/PLAYTEST.md` ほか）。
> 数値の出典は `ファイル:行` で示す。行番号は初回コミット `89b29f1` 時点。
> 本書はコードを一切変更していない。

## 0. 結論の要約

EMBERWHEEL の見た目は、**全員が同じ1つの塗り関数（`Art.shape`）と同じ線幅・同じ光源で描かれていること**で統一感を得ています。そのうえで、**キャラクターだけが明るく、背景は暗く沈み、光源だけが加算で光る**という明度の階層が、キャラクターを引き立てています。そして、**呼吸・まばたき・遅れて揺れる付属物が常に動いている**ことで、キャラクターが生きて見えます。

美術的な魅力のほとんどは、次の4層に分解できます。

1. **描画プリミティブの統一**: インク輪郭3px、フラット塗り、三日月影1段、左上光。
2. **明度の分離**: 背景とキャラクターを明度で分け、光源だけを加算グローで光らせる。
3. **シルエットと記号**: 1キャラクターに1つの特徴的な小道具を持たせ、目の文法で敵味方を描き分ける。
4. **時間軸**: 呼吸、まばたき、二次動作、予備動作とオーバーシュート、ヒットストップ。

テーマ（蝋燭、劇場、スロット）は、この4層の上に載った「衣装」にすぎません。

# 1. 見た目を構成する要素の分解

## 1.1 Art Direction

| 問い | 答え |
|---|---|
| 一言で | **「インクで縁取った紙人形が、暗い舞台で灯りに照らされて演じている」**（灯火の切り絵劇場）。 |
| 最も「らしさ」を作る要素 | 次の3つの重ね合わせ。(1) `#1a1222` のインク輪郭（太さ3px、角は丸め）。(2) 光が左上から来るため右下に出る、硬い三日月影。(3) 暗い紫紺の背景に、暖色の加算グローが点在する明度構成。 |
| なくても画風が保たれる要素 | 劇場の額縁（プロセニアム）と幕、蝋燭や灯輪のモチーフ、パララックス4層、背景の空気表現（埃・霧・灰）、関連エピソードを示す細部（鎖帷子の環、そばかす、帽子の継ぎ当て）。これらは魅力を足しているが、無くしても**画風の同一性**は崩れない。 |
| 転用時に残すべき核 | `Art.shape`（三日月影の塗り）、線幅トークン（3 / 2 / 1〜1.6）、固定パレット（インク色と、基本色・影色のペア）、明度の階層、目の文法、待機中の呼吸とまばたきと二次動作、予備動作とオーバーシュートのキー配分。 |

**判断の根拠**: 初期の設計批評（4視点ワークフロー）は、ドキュメント段階で「紙・磨いた真鍮・石板・ピクセルフォントが混在している」「画面上に"劇場"を示すものが何もない」と指摘していました。これを受けてフォントを Kaisei Decol / Zen Maru Gothic に統一し、舞台装置を追加しています。逆に言えば、**統一感を壊すのは素材やフォントの混在**であり、テーマ要素の多さではありません。

**導かれるルール**

- **頭身は 2.0〜2.3**。指示書では「2.5頭身」と書きましたが、実装はもっと寸詰まりになっています。頭が身長の約45〜50%を占めます。
- **頭の幅は胴の幅の 85〜95%**。頭を胴とほぼ同じ幅にすることで、ちびキャラの「かわいさ」が生まれます。
- **腕は身長の約15%**、**脚は 0〜20%**。手足は短く、演技は主に胴の傾き・伸縮と頭の傾きで行います。
- **3人の差は、外接矩形の比で付けています**。横長で角ばった騎士、縦長の魔女（帽子で高さ1.93倍）、丸い僧侶です。全高も 108 / 124 / 136 と段違いなので、頭のラインが揃いません。

### 小さく表示しても誰か分かる理由

1. **頭上に付属物が突き出ていて、その形が3人とも違う**（羽根、蝋燭付きの円錐、なし＝丸い頭頂）。シルエットの最上部が識別子になっています。
2. **外接矩形の比が違う**（1.30 / 1.93 / 1.32）。騎士と僧侶は比が近いですが、角ばった兜か丸いフードかで区別できます。
3. **主色が明度・色相とも分かれている**: 騎士は鋼 `#d8e2f0` と青緑 `#2f6f8f`、魔女は紫 `#6a3fa0`、僧侶はクリーム `#eadfc4`。
4. **持ち物の位置が違う**: 剣は上向きの縦線、杖は斜め、香炉は下に吊るす振り子。

## 1.3 Line（線）

| 種類 | 太さ | 出典・用途 |
|---|---|---|
| 外輪郭（シルエット） | **3px**（`Art.LW`） | `art_core.js:31`。結合と端は round |
| 内部の主要線 | **2px**（`Art.LW_THIN`） | 顔の枠、帯、服の縁、小さなパーツの輪郭 |
| 中間 | 2.5〜2.8 | 騎士の面頬の開口 2.6、眉 2.8（`heroes.js:572, 629`）、敵の顎や指 `LWT+0.5`（enemies_b で15回） |
| 細部 | 1.0〜1.6 | 皺、縫い目、リベット、口（1.6〜1.8）。色はインクではなく**影色**で引くことが多い |
| テクスチャ | 1.0（α 0.45） | 鎖帷子の環（`heroes.js:531`）。輪郭の内側にクリップして描く |
| 細い棒状の物（杖、紐、尻尾） | 塗り幅 w ＋ 下敷きのインク (w+3) | `inkStroke`（`heroes.js:180`）、敵は `w+LW*2` |
| 背景の切り絵 | 既定 2.5（2〜3） | `backgrounds.js:110-112`。キャラクターより一段細い |
| 背景の遠景の細部 | 1.2〜2 | 遠いものほど細い |
| UIの数字の縁取り | `max(4, size*0.18)` | `fx.js:170`、`scene.js:184`（`size*0.22`） |
| バナー文字の縁取り | 9 | `fx.js:207` |

**どこに線を引き、どこを塗りだけにするか**

- **必ず線を引くもの**: 物体のシルエット全体、目の白目、顔の輪郭、手、武器。
- **影色や細線で済ませるもの**: 服の皺、縫い目、髪の房。インクではなく影色や暗い同系色で引きます（例: 皺は `PAL.witchRobeShade` の1.4px、`heroes.js:1021`）。
- **線を引かないもの**: 炎（`Art.flame` は既定で輪郭なし）、グロー、頬の赤み、汗のハイライト、魔法の軌跡（加算合成の帯）、粒子。光るものと柔らかいものには線を引きません。
- **形の内側の模様は輪郭でクリップ**します（鎖帷子、縞の靴下、帯など）。最後に外輪郭を描き直し、模様のはみ出しを隠します（`knTorso` の手順: 塗り → clip して模様 → 外輪郭を再ストローク）。

**解像度が変わったとき**

- 論理座標を 1280×720 に固定し、キャンバスの実ピクセルは `renderScale = clamp(s*dpr, 1, 3)` 倍にします（`main.js:54-58`）。線幅は論理pxで指定するので、画面サイズが変わっても**見た目上の太さは一定**です。
- 記号・アイコン・遺物は**サイズに比例した線幅を上下限で制限**します。
  - 記号: `clamp(size*0.052, 1.8, 4.4)`（`symbols.js:327-330`）
  - アイコン: `clamp(size*0.068, 1.5, 3.2)`
  - 遺物: `clamp(size*0.056, 1.5, 4.2)`
  - 出来事の挿絵: `clamp(size*0.027, 1.2, 3.6)`
  - 内部線は外輪郭の **0.6〜0.62倍**。
- 内部で拡大縮小するパーツは **`lw / scale`** で太さを補正します（蛾の羽 `Art.LW/scl`、アイコン `L.lw/0.9`）。**画面上で常に同じ太さに見せる**ためです。
- キャッシュは解像度係数 `res` を 0.25 刻みに量子化し、0.5〜4 に制限してキーに含めます（`symbols.js:449-469`）。

### 基本色と影色の関係（実測）

| 素材 | 基本色 → 影色 | 明度の変化 | 色相の変化 |
|---|---|---|---|
| 布（陣羽織） | `#2f6f8f` → `#1f4a63` | 約 −33% | なし |
| 布（ローブ） | `#6a3fa0` → `#472a72` | 約 −30% | なし |
| 肌 | `#ffd9b8` → `#e8a98a` | 約 −15% | **赤みへ寄せる**（血色の影） |
| 骨・クリーム | `#efe5cf` → `#c9b994` / `#eadfc4` → `#bfae88` | 約 −18% | 黄土側 |
| 鋼 | `#d8e2f0` → `#8e9cb8` | **約 −35%（落差が最大）** | 青へ寄せる |
| 真鍮 | `#c9953b` → `#7a5520` | 約 −40% | 茶色へ |
| 髑髏（記号） | `#efe5cf` → `#b39dd8` | −20% | **紫へ**（呪いの色を影に入れる） |

**ルール**

- **影は明度を 15〜40% 下げる**。下げ幅は素材で変え、柔らかいもの（肌、骨）は小さく、金属は大きくします。
- **影は単純に暗くせず、意味のある方向へ色相をずらす**（肌は赤、鋼は青、呪いは紫）。
- **体の奥側のパーツは、さらに一段暗い「Back」色を使う**。例: 鎖帷子 `#8d91ad` → 奥側 `#6a6d88`、鋼 → `steelBack #a9b5cc`、魔女の奥の脚 `#1f1530`。陰影ではなく固有色そのものを奥側だけ暗くして、奥行きを出しています。

### 背景色とキャラクター色の分離

- 背景は**低明度・低彩度**です（地下蔵の壁 `#4b3040`〜`#56384a`、背景グラデーション `#0b0710` → `#33202a`）。
- キャラクターの主色は**中〜高明度**です（鋼、クリーム、肌、骨）。暗い主色（紫の魔女）には、明るい肌と橙の髪、黄色い蝋燭を重ねて明度差を確保しています。
- さらに舞台全体に暗いグラデーションを重ねて背景を一段沈めます（α 0.42 → 0.22 → 0.16 → 0.30、`scene.js:126-128`）。演技帯（y 200〜390）には霞（α 0.10〜0.14）をかけ、周囲にはビネット（α 0 / 0.32 / 0.78）をかけます。

### 「予約色」の考え方

- スロットの記号7色は**ゲームの意味を持つ色**です。背景やキャラクターの面積の大きい部分には使いません。
- 守られた例: 盾の空色 `#6fd3ff`、癒の翠 `#7df0b4`、呪いの紫 `#9b7bd6` は背景に一度も出てきません。
- **破った結果起きた失敗**: 留め具の印に、盾の色 `PAL.ward` の盾形を使ったところ、新規プレイヤーが「盾の記号に見える」と誤読しました。真鍮の南京錠と赤いリボンに置き換えています（§5参照）。
- 予約色に近い色は、背景でも**暗く、または小さく**使います。例外として、背景の炉の口や星に `#ff7a2f` `#ffd257` `#fff6d8` が残っています（`backgrounds.js:1625, 1890, 2334`）。
- 汎用化するなら**機械的に検査できるルールにするべき**です。設計批評の提案では「背景に予約色の色相を明度50%超で使わない」としていました。

| ガラス・宝石 | 透明感のある色 | **影の向きを反転**（+5, +4）で凹んで見せる | 白い菱形 | — |
| 石（装置の面） | 暗い紫 | 影の向きを反転（+4, +5）で彫り込んで見せる | — | 目地1.2px、斑点 |
| 木 | 茶 | −35% | — | 木目線 |

**素材の違いは主に「ハイライトの強さ」と「影の落差」で表しています**。金属は α 0.65 と −35%、布は α 0.13 と −30%、炎は影なし・輪郭なし・加算です。形が同じでも、この2つの数値だけで素材が変わって見えます。

## 1.5 Light & Shadow（光と影）

| 項目 | 値 |
|---|---|
| 光源の方向 | **左上で固定**（`art_core.js:7`）。舞台装置としての光源は下中央のフットライト（灯輪）で、これはグローだけで表現する |
| 影の方向 | 右下の三日月 |
| 影の幅（オフセット） | 既定 (−4, −4)。ヒーローは `k` を指定（胴4、兜5、帽子3.5、手2、剣2.3、小物1.2〜1.5）。敵は大きな塊 −6〜−8、中くらい −4〜−5、小物 −1〜−3。記号は100単位の箱に対して −7（7%） |
| 影幅の目安 | **パーツの幅の 8〜10%（大きいもの）、15〜25%（小さいもの、最低でも約1.2px）** |
| 回転するパーツ | `ROT` に累積回転角を記録し、オフセットを逆回転させる。**腕を振っても倒れても、光は世界座標で左上のまま**（`heroes.js:45-56`、ボスの `litOff`） |

### `Art.shape` の三日月影がなぜ効くのか

```text
① 形全体を影色で塗る
② その形でクリップする
③ 同じ形を (dx,dy)=(-4,-4) にずらし、基本色で塗る
     → ずらした分だけ右下に影色が残り、三日月になる
④ （任意）ハイライトの点をクリップ内に置く
⑤ 元の位置でインク輪郭を引く
```

- **形から影が自動で決まる**。影の形を手で描かないので、どんな blob でも、何百個のパーツでも同じ光の論理になります。AIが量産しても破綻しにくいのはこのためです。
- **境界が硬い**。グラデーションではなく二値で塗り分けるので、切り絵や版画の質感になります。グラデーションは「光」専用にとってあるため、光と物体の区別がはっきりします。
- **立体感が最小コストで出る**。凸形状の右下にだけ影が出るため、平面の切り絵でも「ふくらんだ紙」に見えます。
- **輪郭線のすぐ内側に影が来る**。右下で、インク線と影色が太い帯として連続し、シルエットの重さ（接地感）を作ります。
- **向きを反転すると凹みになる**。ガラス・宝石・石の面に使っており、1つの関数で凹凸の両方を表現できます。

### ハイライト

- `opts.hi` で、クリップの内側に楕円を1つだけ置きます。左上寄りに置き、縦長にするのが基本です。
- 素材による強さ: 鋼 α 0.65、盾 α 0.2、布 α 0.12〜0.14、敵の骨や兜 α 0.3〜0.4。
- 金属には追加で**細い白い線**（刃の左縁、兜の縦線、面頬の下縁）を引きます。

### Glow（加算グロー）を使う場所と使わない場所

| 使う | 使わない |
|---|---|
| 光源: 蝋燭、炎、結晶、香炉、敵の目、宝石、ルーン | 体、服、肌などの物体の面 |
| 魔法・攻撃の瞬間: 斬撃の先端 r30、詠唱 r34、防御 r34、留め r40 | 影（影は必ず硬い塗り） |
| 危険の予告: 溜めのオーラ、致命の予告板 r90 | 常時、画面の大部分を覆うもの |
| 舞台照明: フットライト r520〜640、α 0.16〜0.20 | |

- 実装: `globalCompositeOperation='lighter'` の放射グラデーション（中心の色 → 透明、`art_core.js:134-145`）。
- 目安の半径: 炎は大きさの3.2倍、敵の目は大きさの3倍（α0.8）、粒子は大きさの2.6〜3.2倍。
- キャラクターのファイルではグラデーションを一切作っていません（グローを除く）。ルール「No soft gradients on characters」は守られています。

## 1.6 Character Construction（キャラクターの組み立て）

### 構造: 「リグ（数値）」と「レンダラ（描画）」の分離

```text
pose, t, p ─► xxxRig() ─► r = { x,y,rot,px,py,sx,sy,    // 体全体（ピボット付き）
                                hr,hx,hy,               // 頭（首を支点）
                                aN,lN,w, aF,lF,         // 手前の腕の角度と長さ、武器の角度、奥の腕
                                ffx,ffy,fbx,fby,        // 手前と奥の足のオフセット
                                eye,brow,mouth,blink,   // 表情
                                固有値 (shS, hatY, ch, glow...) }
           ─► drawXxx(ctx, r) : パーツを決まった順番で描く
```

- リグは**純粋な数値**です。そのため、過去の時刻で再計算して二次動作の遅れを求めたり（`lagOf`）、軌跡を取って斬撃の帯を作ったり（`knSwoosh` は 14 サンプル）できます。
- ポーズは**キーフレーム表**です。`K(p, イージング, {変化する値だけ})` を並べて `track()` で補間します。省略した値は前のキーから引き継ぎます（`heroes.js:66-85`）。

### パーツ構成（騎士、全部で約14部品）

| # | 部品 | 作り方 | 関節・支点 |
|---|---|---|---|
| 1 | 奥の腕 | カプセル（幅10、奥側の色） | 肩 `shF [-15,-47]`、角度 aF、長さ lF |
| 2 | 盾（通常は奥） | 円 R19、縁は真鍮、リベット8個、紋章 | 奥の手＋オフセット (shDX, shDY) |
| 3 | 奥の脚 | カプセル10＋鉄靴（奥側の色） | 腰 `hipB [-9,-15]` |
| 4 | 手前の脚 | カプセル10＋鉄靴 | 腰 `hipF [9,-15]` |
| 5 | 胴 | 10点の blob（鎖帷子）、環のテクスチャ、陣羽織、徽章、ベルト | 体全体の基準 |
| 6 | 奥の肩当て | 楕円のドーム | 胴に固定 |
| 7 | 頭 | 羽根 → 兜の頂 → 兜（角丸の多角形）→ 面頬の開口 → 顔 → 目・眉 | **首 `[3,-50]` を支点に回転** |

| 10 | 盾（前に出すとき） | 防御と留めのときだけ、最前面に描き直す | |
| 11 | 演出 | 火花、グロー、汗、魂の灯 | 世界座標 |

### 描画順の原則（3人共通）

```text
[背面の演出（斬撃の軌跡）] → 奥の腕 → 奥の持ち物 → 奥の脚 → 手前の脚 → 胴 → 頭（後ろ髪 → 顔 → 前髪 → 帽子）
→ 手前の持ち物 → 手前の腕 → 手 → [前面の演出]
```

- **状況に応じて順番を入れ替える**: 剣を大きく振りかぶったとき（`aN > 2.62`）は、手前の腕を頭より奥に描きます（`r.nBack`）。盾を前に出したときは最前面に描き直し、縁を握る拳も描きます。
- **斬撃の軌跡はキャラクターの後ろに描く**（`heroes.js:675`）。シルエットが潰れないようにするためで、自己批評の段階で修正されたものです。
- 魔女と僧侶の袖は、**腕と一緒に回転するが、袖口だけは世界座標の下に垂れる**ようにしています（`bellSleeve`）。布の重さの表現です。

### 武器の持たせ方

- **武器は手の座標を原点とし、腕の角度とは別の角度 `w` を持つ**。手首が独立して返せるので、振りかぶり（w −0.72）から振り下ろし（w 1.8）までの大きな弧が作れます。
- 握りの表現: 柄の上に、手（籠手、または肌色の円 r3.7〜4.4）を後から重ねて描きます。
- 武器の大きさ: 大剣は約78（身長の64%）、杖は約94（帽子を除いた身長の115%）、盾は直径38（31%）。**武器は誇張して大きくする**のが基本です。
- 先端の座標は `info.fx` として登録し、演出の発生位置に使います。idle のリグから計算します（`heroes.js:1619-1620`）。

### 二次パーツ（羽根・帽子・髪・鎖・リボン）

- **背骨（spine）の点列 ＋ 点ごとの半幅 ＋ 点ごとの揺れの重み**で作ります（`spineOutline`）。
  - 羽根: 背骨6点、半幅 `[3.6,6.2,7.6,6.8,5,2.2]`、重み `[0,0.1,0.3,0.55,0.8,1]`（`heroes.js:576-578`）。
  - 帽子: 背骨6点、半幅 `[16.5,12,8.2,5.4,3.7,2.7]`、重み `[0,0.05,0.2,0.45,0.75,1]`（`heroes.js:949-951`）。
  - **根元は動かず、先端ほど大きく動く**。重みは2次曲線に近い分布です。
- 揺れは2つの成分の和です。
  - (a) 時間による正弦波: 羽根 `sin(2.3t)×2.2`、帽子 `sin(1.9t)×2.2`、お下げ `sin(2.6t)×1.5`。
  - (b) 体の速度による遅れ `lag`: 0.06秒前のリグとの差を ±14px で制限し、係数 0.6〜1.15 を掛けます。
- **世界座標で上を向き続けるもの**: 帽子の先の蝋燭（`rot(-ROT)`）。炎は常に上へ伸びます。

### シルエットを崩さないためのルール

1. 演出（軌跡、オーラ）はシルエットの**後ろ**に描くか、加算合成で**半透明**にする。
2. 手前の腕・手・武器は、胴や顔の**外側**に出るポーズを優先する。重なる場合は輪郭線で分離する。
3. 頭上の識別パーツ（羽根、帽子、フード）は**どのポーズでも見える**ようにする。
4. 体全体の伸縮（squash & stretch）は **sx と sy を逆方向に**動かし、体積を保つ。
5. 倒れたポーズの幅は 100〜130 になり、隣と重なりうる（既知の未解決課題）。

### 敵のアニメーション（共通の曲線）

- **突進の曲線 `lungeK`**（`enemies_a.js:27-33`）:
  - p 0〜0.3: 後ろへ −0.32（easeOut）。
  - 0.3〜0.44: 前へ +1.08（easeIn、8%行き過ぎ）。
  - 0.44〜0.58: 1.0 に戻って落ち着く。
  - 0.58〜1: 元の位置へ。
  - 突進距離は 40〜64px。
- **体全体の動き `motion()`**（`enemies_b.js:39-55`）:
  - 後ろへ 10〜14px、前へ 26〜50px。
  - 引くときは sx 1.05 / sy 0.95、突くときは sx 0.95 / sy 1.06。
  - ボスは前へ 26px だけで、わざと重く見せています。
- **溜め（windup）は必ず次の3点セット**:
  1. 高周波の震え（38〜61rad/s、0.7〜1.6px）。
  2. 構えを保つ姿勢（しゃがむ sx 1.07 / sy 0.9、または 0.07〜0.2rad 仰け反る）。
  3. **危険の光**（蝋燭の炎が1.6倍、鐘の音の輪、床の呪いの印、刃の光など）。
  - 加えて、目を細めます（`slit:1`）。
- 被弾（hit）: `pulse(p, 0.12)` で反動します。B側は横揺れ `sin(p×55)×3×(1−p)` を加えます。
- 消滅（die）: 透明度を `(1−p)^1.7` で下げ、画面外のキャンバスに1枚にまとめて描いてから合成します。**重なった部品が透けない**ようにするためです。

### 「生きているキャラクター」に見せる技法と数値

| 技法 | 実装 | 数値 |
|---|---|---|
| **anticipation（予備動作）** | 打撃の前に逆方向へ引く。体を潰し、後ろへ傾ける | 時間全体の **約30%**（0.0〜0.3）。x −5、回転 −0.15、sy 0.92。敵は −0.32（引き幅は前進の約30%） |
| **打撃** | easeIn で一気に進む | 時間全体の **約12%**（0.3〜0.42 ＝ 0.42秒中の約50ms） |
| **overshoot（行き過ぎ）** | 目標を越えてから戻る。easeOutBack や、キーで直接行き過ぎを置く | 敵の突進 +8%、防御の構えは easeOutBack（c1=1.70158）、倒れたときの2回の跳ね返り（8% → 3%） |
| **follow-through（余韻）** | 打撃の後、すぐ戻らずにポーズを少し保つ | 0.42〜0.56（約14%）。戻りは0.56〜1（約44%）を easeInOut で |
| **squash & stretch** | sx と sy を逆向きに | 予備動作・着地で 5〜15% 潰す（sy 0.85〜0.92）、跳躍・打撃で 5〜9% 伸ばす（sy 1.06〜1.09） |
| **secondary motion（二次動作）** | 羽根、帽子、お下げ、香炉、リボン、小瓶、尻尾、旗 | 根元0〜先端1の重み、正弦波＋速度による遅れ（0.06秒前との差、±14px） |
| **breathing（呼吸）** | sy と sx を逆位相で、頭は少し位相をずらして | 周期: 騎士 1.9秒、魔女 1.7秒、僧侶 2.1秒、ネズミ 1.4秒、猟犬とゴーレム 2.2秒。振幅: sy ±1.8〜2.4%、sx ∓1.0〜1.6%（sy の約0.55〜0.67倍）、ネズミは ±3%。頭 ±0.7〜0.8px |
| **blink（まばたき）** | 周期 `3.3 + seed×1.1` 秒、長さ 0.15秒の sin 波 | 騎士 3.52秒、魔女 4.13秒（seed>0.5 なので0.12秒の間を置いて**2回まばたき**）、僧侶 3.74秒（0.28秒の**眠そうな**まばたき）。敵A 3.9秒 / 0.18秒 |
| **delay（ずらし）** | 全員が同時に動かないようにする | 各 Actor に `t0 = random×10` を与える（`scene.js:16`）。二次揺れの周波数を整数比にしない（1.9 / 2.3 / 2.6 / 3.4 rad/s）。呼吸の周期は人ごとに違う |
| **大きさと速さ** | 小さい者ほど速く、大きい者ほど遅い | 歩行周期: 魔女 0.46秒（上下3.4）、騎士 0.56秒（2.6）、僧侶 0.62秒（2.2）。ボスは前進を最小に |
| **ポーズの保持** | 溜め・構え・倒れは、one-shot が終わっても保持する | `Actor.setHold`。保持中も t によるループ（震え・グロー）は続く |

# 5. 良いキャラクターと悪いキャラクターの違い（実際の事例）

## 5.1 うまくいった例と、その理由

| 対象 | なぜ良いか |
|---|---|
| ブラム | 頭上の羽根、四角い兜、丸い盾、長い剣という**4つの形の系統**を1体にまとめつつ、主色は鋼に統一している。面頬から見える大きな目が、硬い鎧に親しみを足している |
| ルゥ | 体より大きい帽子が**シルエットの70%以上を決めている**。帽子の先の蝋燭は世界座標で上を向き続けるので、どのポーズでも識別できる |
| トト | 丸、クリーム、振り子という**低い刺激**で、癒し役の性格が形と動き（呼吸の周期が最も遅い 2.1秒、眠そうなまばたき 0.28秒）に出ている |
| 鐘つき犬（精鋭） | 溜めの「遠吠え」で、頭を 1.02rad 仰け反らせ、鐘を振り、音の輪を3重に出す。**次のターンに強撃が来ること**が、絵だけで読める |
| 修道院長 | 縦長の三角形のシルエット（高さ215）が、精鋭の威圧感をサイズと形の両方で出している。自己批評で「Abbot reads well now」 |
| 灰輪の主 | 段階ごとに、回転速度・炎の大きさ・色（紫 → 赤）・欠損（スポーク、縁）が**単調に増える**。段階の進行が絵で分かる |

## 5.2 修正が必要だった例

| 分類 | 事例 | 問題の本質 | 修正 |
|---|---|---|---|
| **意味の衝突（色と形）** | 留め具の印が**空色の盾** | 予約色（盾＝`#6fd3ff`）と盾の記号の形が重なり、「盾が出ている」と誤読された。しかも上のマスを覆っていた | 真鍮の南京錠とブラムの赤いリボンに変更。マスの外（上）へ移動。内側の線も空色から真鍮色に |
| **小さいサイズでの意味の誤読** | 砥石が「本棚の本」、火打金が「フック → スプーン」、鑿が「ペン」、鏡が「虫眼鏡」、階段が「光るトンネル」 | 28px で**シルエットが別の日用品と同じ**になる | 砥石は刃を研いでいる場面に、鑿は幅広の刃を太く、階段は3D投影の階段に、火打金は暗い鉄と明るい打撃面に。44px 未満の small モードでは細部を削り、要の部品を1.1〜1.3倍に |
| **シルエットが弱い・ごちゃつく** | 殻ムシの板が多すぎた。ネズミの尻尾が長すぎた | 情報量がシルエットの読みやすさを上回った | 「fewer, calmer plates」、尻尾を短く巻き、全体を 0.9倍に、脚を太く |
| **重なりで識別できない** | 騎士の斬撃の軌跡が体に重なった。腕や盾がパーツの中に隠れた | 演出がシルエットを覆った | 軌跡を体の後ろに。腕・盾の位置と描画順を調整し、盾の縁を握る拳を追加 |
| **アニメーションが硬い** | 袖が腕と一緒に剛体として回った | 布の重さがない | 袖口だけ世界座標の下に垂らす（`bellSleeve`） |
| **アニメーションが硬い** | 香の煙が体に貼り付いて見えた | 世界座標で動いていなかった | 世界座標で立ち上り、フェードする2本の煙に |
| **消え方の破綻** | 消滅時、重なったパーツが透けて継ぎ目が見えた | パーツごとに α を掛けていた | 画面外のキャンバスに1枚として描いてから α を掛ける（`layered`、`fadeLayer`） |
| **静止画の破綻** | 幽霊の彫り師のまばたきが t=0 に同期していた | キャッシュした静止画で常に目が閉じていた | まばたきの位相をずらす |
| **背景に埋もれる・背景が勝つ** | 祭壇やシャンデリアが演技帯で明るすぎた。橙の火鉢（予約色）。炉が隊列の真後ろ。床の蝋溜まりが「明るいゴミ」に見えた。グローが強すぎた | **明度の階層が逆転**した | 舞台全体を暗くするグラデーション（α 0.42 → 0.16 → 0.30）、フットライト、明るい炉の位置をずらす、蝋溜まりを暗く。背景エージェントは「まず環境を暗くし、その上に蝋燭の光の溜まりを足す」順番に変更 |
| **見えない・小さすぎる** | 火種の蝋燭が size 1 で見えなかった。26 にしても背景の飾りに見えた | 重要な UI がキャラクターの画風に溶けた | 34 に拡大し、棚に載せ、残数を表示し、使う分を点滅させる |
| **UI がキャラクターを覆う** | 敵の名前がパペットに重なった。チュートリアルの吹き出しが発動列を隠した。バナーが重なった | 情報レイヤーの配置規則がなかった | 名前は HP バーの下へ。ヒントは盤面の外に下向き矢印付きで。バナーは新しいものが出たら古いものをフェード |
| **演出が強すぎる** | コンボの画面フラッシュ α0.55 | 画面全体が白飛びし、キャラクターが消えた | α0.3 に |
| **画風の混在** | 初期設計: ピクセルフォント＋紙＋真鍮＋石 | 素材の言語が統一されていない | フォントを Kaisei Decol / Zen Maru Gothic に。UI はすべて「真鍮の縁の石板」に統一し、CSS 変数を PAL と同じ値に |
| 未解決 | 倒れたヒーローが幅 100〜130 で隣と重なる。盾と腕の描画順が動作中に切り替わり、一瞬ちらつく | — | 既知の課題として残っている |

**計画したが実装されなかったもの**（正直な記録）

- 設計批評では「精鋭 3.5px、ボス 4px、記号 2.5px」と線幅の階層を提案しました。しかしアート担当エージェントの起動が設計改訂（v0.2）の9分前だったため、実装では全員 3px のままです。
- 共有のパペットシステム（JSON 定義）も提案されましたが、各エージェントが個別にリグを手書きしました。
- 汎用化するときは、この2点を最初から Harness に入れるべきです。

## 5.3 今後 AI が自動生成するときに避けるべき失敗

1. **意味のある色や形を装飾に流用しない**。予約色、予約された形（盾、ハート、髑髏）を装飾や UI のマークに使うと、プレイヤーが誤読します。
2. **小さいサイズで、シルエットが別の日用品にならないか確認する**。28〜44px での「それは何に見えるか」テストを必須にします。
3. **細部を増やしすぎない**。板・棘・皺を増やすほど、シルエットは弱くなります。「少なく、落ち着いて」。
4. **演出をシルエットの前に置かない**。軌跡は後ろに、グローは加算で半透明に。
5. **布や付属物をボディと剛体で動かさない**。根元0〜先端1の重みと、世界座標の重力を使います。
6. **パーツごとに α を掛けて消さない**。1枚に合成してから消します。
7. **すべての周期を t=0 で揃えない**。まばたき、呼吸、揺れの位相と周波数はキャラクターごとにずらします。
8. **背景を明るくしない、背景で予約色を使わない**。まず暗くしてから光を足します。
9. **プレビューの無地背景だけで判断しない**。実際の背景・UI・演出と重ねて確認します。
10. **重要な UI を画風に溶け込ませすぎない**。ゲームプレイ上重要なものは、キャラクターより目立つ大きさとコントラストにします。
11. **影をパーツごとに手描きしない**。必ず共通の `shape()` を通し、回転したパーツでは光の方向を補正します。
12. **輪郭線の太さを場当たり的に決めない**。トークン（3 / 2 / 1.x）か、大きさに比例する式で決めます。
13. **キャラクターにグラデーションを使わない**。グラデーションは光だけに使います。

7. 回帰確認（〜15:36）

これを一般化すると、次の10工程になります。

| # | 工程 | 入力 | 出力 | チェック内容 | 完了条件 |
|---|---|---|---|---|---|
| 0 | **アート方針の言語化** | ゲームの企画、トーン | 一言コンセプト、アート方針の文書（色、線、光、頭身、動きの原則） | 素材・フォント・光源が1つの「世界のルール」で説明できるか。テーマがゲームの読みやすさと衝突しないか | 批評エージェント（読みやすさ、実現性、一貫性）の指摘を反映済み |

| 9 | **プレイテストとレビュー** | 動くゲーム | 指摘の一覧（新規プレイヤー、中級者、アートディレクター、システム、コード） | 誤読（意味の衝突）、明度の階層、重なり、情報の優先度 | 指摘ごとに「直す / 直さない（理由）」を決める |
| 10 | **改善** | 指摘 | パッチ、変更記録 | 回帰（スモーク、キャプチャ） | 文書（PLAYTEST）に記録した |

**このプロセスで効いたこと**

- **style kit を最初に書き、制作中は変更しなかった**（`art_core.js` は一度も変更されていない）。6人が並列で描いても、線・影・パレットが揃いました。
- **契約で「呼び出し側がやること」を明記した**（接地影と白フラッシュは描かない）。統合時の二重描画を防げました。
- **自己批評を指示書で義務にした**（「アートディレクターのように正直に批評し、2周以上改善する」）。
- **プレビューに URL パラメータを付けた**（フィルムストリップ、crop、zoom）。AI が静止画で細部を確認できるようになりました。

**このプロセスで問題になったこと**

- 設計の改訂（v0.2）がアート担当の起動より後でした。**方針を確定してから制作を始めるべき**です。
- ブラウザのタブ数の上限、ペインが隠れたときの rAF の間引き（2〜8fps）、`file://` の静止画化、ヘッドレスの仮想時間でのハング。**キャプチャ用の仕組み（`POST /__shot`、headless、フィルムストリップ）を Harness の標準機能にする**べきです。
- 指示書の文言（「盾の紋章付きの留め具」）がそのまま誤読の原因になりました。**指示書も予約色・予約形のルールで検査する**必要があります。
- プレビューは無地の背景だったため、背景との明度の衝突は統合後まで見つかりませんでした。**プレビューに背景を切り替える機能を入れる**べきです。

# 8. 最小構成: 80% を再現するために必要なもの

## 必須（これだけで約80%）

| # | ルール・機能 | 寄与の目安* | 実装量 |
|---|---|---|---|
| 1 | `shape()`（三日月影）＋ インク輪郭 3/2px（round） | 25% | 約25行 |
| 2 | パレット: 有彩色のインク ＋ 基本色と影色のペア（明度 −15〜−40%）＋ 奥側用の Back 色 | 10% | 定数のみ |
| 3 | 明度の階層: 暗く低彩度の背景、舞台を暗くするグラデーション、接地影 | 12% | 約20行 |
| 4 | 加算グロー（光源専用）＋ キャラクターにグラデーションを使わない | 8% | 約10行 |
| 5 | 2頭身強のちびの比率 ＋ 頭上の識別パーツ ＋ 誇張した持ち物 | 10% | 設計ルール |
| 6 | 目の文法（味方は白目・瞳・キャッチライト、敵は発光） | 5% | 約40行 |
| 7 | `blobPath` | 3% | 約12行 |
| 8 | キーフレームの `track()` ＋ キー配分 30/12/14/44 ＋ squash | 4% | 約25行 |
| 9 | idle の呼吸（sy ±2%）＋ まばたき（3.5〜4秒、位相ずらし） | 2% | 約15行 |
| 10 | 白フラッシュ ＋ ヒットストップ ＋ 揺れ ＋ インク縁の数字 | 1%（見た目）／手応えへの寄与は大 | 約60行 |

\* 寄与の目安は計測値ではなく、本分析による判断です。「それを外したら、どれだけ EMBERWHEEL らしさが失われるか」の主観的な順位付けです。

## なくても致命的ではないもの（後から足す）

- 回転したパーツでの光の方向の補正（`ROT`）。回転が小さいうちは目立ちません。
- 速度による遅れ（`lagOf`）。単純な正弦波の揺れで代用できます。
- 袖口を世界座標の下に垂らす処理、倒れたときに持ち物が転がる演出、魂の灯。
- 4層のパララックス、空気の粒子（埃・霧・灰）、水面の反射。
- 鎖帷子の環、そばかす、継ぎ当てなどの模様（クリップして描く細部）。
- 記号・遺物の解像度の量子化キャッシュ（性能のためだけの機能）。
- 遺物の small モード（小さい表示がなければ不要）。
- 敵の消滅を1枚に合成してから消す処理（消滅演出が短ければ目立たない）。
- 劇場の額縁、幕、エプロン（テーマ要素）。

## 過剰設計を避けるための線引き

- まず 1〜9 だけで、**1キャラクター＋1背景＋idle と攻撃と被弾**を作り、EMBERWHEEL と並べて比較します。
- 足りない部分を特定してから、「なくても致命的ではない」リストから足していきます。
- 素材プリセット・JSON 定義・読みやすさの自動検査は、**3体目のキャラクターを作るとき**に導入するのが適切です。それまでは手書きで十分です。
